# elementary_bot

Телеграм-бот складу Vatra Bistro. Показує залишки з Elementary POS.

Каса рахує кожну позицію в чомусь одному: сиропи в літрах, коли в штуках,
каву в кілограмах. Дивляться ж на обидві міри — літри сходяться зі списанням,
пляшки з полицею й замовленням постачальнику. Тому бот показує і те, і те,
а тару бере з назви товару: `Becherovka 38% [1 l]`, `Vareniky s masem
[13 ks/porce]`. Міняти тару можна в касі, бота чіпати не треба.

## Команди

| | |
|---|---|
| `/stock` | кухня: штуки й порції |
| `/stock bar` | бар і склад: літри й пляшки, окремо вага й поштучне |
| `/stock all` | усе разом |

Кухню від бару бот відрізняє за префіксом SKU `SK-`.

## Налаштування

Змінні оточення (на сервері — `/etc/elementary-bot.env`, локально — `.env`,
який у git не потрапляє):

| | |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен від @BotFather |
| `ELEMENTARY_API_KEY` | ключ Public API каси |
| `ALLOWED_CHAT_IDS` | список id через кому, `all` — відчинено всім, порожньо — нікому |

`ALLOWED_CHAT_IDS` порожній означає «нікому» навмисно: ім'я бота не секрет,
і свіжий бот не має стояти відчиненим. Id кожного чату, що написав, видно
в журналі — звідти його і брати.

## Запуск

```sh
python3 bot.py            # довге опитування телеграма
python3 bot.py --stock    # надрукувати залишки в консоль, без телеграма
```

Другий варіант — найшвидший спосіб перевірити, що ключ каси живий.

Залежностей немає: стандартна бібліотека Python, довге опитування замість
вебхука (домену не треба). На сервері живе як `elementary-bot.service`,
див. `deploy/`.

## Що далі

Кухарі заповнюють друкований бланк — рядки це страви, стовпчики дні —
і надсилають фото. Бот розпізнає цифри, показує прочитане на підтвердження
і вносить у касу як прихід через `/v1/stock/add-stock-change`, по клітинці
на день. Ключ `аркуш · дата · страва` робить повторне фото безпечним.
